# 21.02 Conditional Assignment Identifiability

## Change and reason

The Latin homophonic control has several optimal maps. Its selected map contains an incorrect assignment.
The new prototype tests whether each selected assignment is necessary to attain the certified score.

The [study protocol](../../../docs/plans/optimal-key-identifiability-v1.md) defines the fixed domain and queries.
The [component guide](../../../experiments/identifiability/README.md) describes the implementation.
This follow-up does not change the failed control result or establish a manuscript reading.

The query engine distinguishes a complete witness, a proved exclusion, and an unresolved search.
Each result records the fixed objective fingerprint and search settings.
The runner binds the problem to the published Latin report with source, input, and map hashes.
It saves all assignment decisions before test scoring and planted-assignment diagnostics.

## Verification

Synthetic tests compare bounded queries with complete enumeration on small problems.
Internal review found and corrected mutable input state and an incomplete global-bound calculation.
The global bound now retains branches removed below the query target.
The live-frontier bound remains a separate field.

A separate incremental adapter passed scalar comparisons on synthetic inputs.
Its state constructor is restricted to engine factories.
The first reference study uses full bound recomputation, without that adapter.

Run the checks from the repository root:

```sh
PYTHONPATH=src:. python -m unittest discover -s experiments/identifiability -p 'test_*.py' -v
```

The runner checks the scope of the existing certificate. It does not independently prove the original global optimum.
The source certificate has equal bounds and a byte-for-byte reproduction from a separate public checkout.
These are internal computational checks, not external scholarly validation.
